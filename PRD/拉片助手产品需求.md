# 拉片助手（PianAssistant）产品需求

本文件是拉片助手的产品需求基线，与 `GEMINI.md` 互为补充。
GEMINI.md 是工程规范真源；本文件是功能范围真源。

---

## 产品定位

面向编导的视频拉片辅助工具。核心价值：在视频回放过程中快速截图、
截取片段、记录时间戳笔记，辅助拉片分析工作流。

技术栈：C# / .NET 10 / WPF / LibVLCSharp / ffmpeg.exe。
形态：Windows 10 21H2+ 原生桌面应用，禁止 WebView2/Electron/HTML UI。

## 里程碑路线图

### M0 v0.1.0 — MVP 起步（已完成，2026-10-12）

核心功能落地，覆盖编导拉片的最小可用工作流。

- 多格式视频播放（LibVLC 引擎）
- 快速截图（TakeSnapshot，PNG/JPG 可选）
- 快速片段截取（ffmpeg 流复制/重编码）
- 达芬奇风格快捷键（29 项，KeyBinding 窗口级，W3 可自定义）
- 自定义时间轴控件（刻度+播放头+入出点标记+鼠标拖动 Seek）
- 侧边栏面板切换（播放列表 / 笔记，顶部按钮+Tab 键切换）
- W3 设置窗（输出目录、截图格式、快捷键编辑器）

### M1 — 播放增强（已完成，与 M3 合并交付于 v0.4.0）

- 全屏模式（F 键切换，Esc 退出，鼠标自动隐藏）
- 播放列表拖拽排序、右键菜单（删除/复制路径/在资源管理器中打开）
- 多文件连续播放（EndReached → 自动下一曲）
- 播放速度记忆（每文件独立保存上次 Rate）
- 音量控制（Slider + 静音键）
- 字幕加载（外挂 .srt/.ass 拖拽到视频窗口）

### M2 — 笔记与标记增强（已完成，交付于 v0.5.0）

- 笔记编辑/删除/搜索（按文本/时间范围筛选）

- 系统级全局热键（可选开关，注册 RegisterHotKey）
- 时间轴标记可视化（笔记/截图/片段在时间轴上显示标记点）
- 笔记跳转改进（上一个/下一个笔记快捷键）
- 笔记模板（预设拉片分析模板：构图/灯光/节奏/转场等字段）

### M3 — 项目持久化（已完成，交付于 v0.4.0）

- SQLite 数据库（schema 起步：projects / screenshots / clips / notes 四表）

- 数据迁移（schema versioning + AtomicTextFile 原子升级）

### M4 — 截图与片段管理（已完成，交付于 v0.6.0）

- 截图画廊（缩略图网格浏览、双击放大、左右键翻页）

- 截图/片段标签与筛选（按视频源/日期/标签筛选）

### M5 — 文本驱动批量操作（拓展功能，已完成，交付于 v0.7.0）

根据整理好的固定格式文本，自动批量截图和截取片段。
面向编导在拉片后整理出的时间码清单，一键执行全部操作。

#### 功能描述

用户在拉片过程中或拉片后，整理出一份固定格式的文本清单
（如时间码 + 操作类型 + 可选标签），程序解析后自动批量执行
截图和片段截取，无需逐个手动标记入出点。

#### 文本格式规范（草案）

```
# 拉片清单 — 支持注释行（# 开头）

# 格式1：单点截图
00:01:23            截图 构图-三分法
00:00:42.500        截图 光影-逆光

# 格式2：片段截取（入点-出点）
00:01:30-00:02:15   片段 转场-叠化
00:03:00-00:03:10   片段 节奏-快切

# 格式3：仅标记入出点（不导出）
00:05:00            标记 镜头-全景
00:05:30            标记 镜头-特写
```

- 时间码格式：`HH:MM:SS` 或 `HH:MM:SS.fff`（毫秒可选）
- 片段格式：`入点-出点`（连字符分隔）
- 操作类型关键字：`截图` / `片段` / `标记`
- 末尾可选标签：空格分隔的任意文本
- 空行和 `#` 开头行忽略

#### 交互流程

1. 用户在笔记面板或外部文本编辑器整理清单
2. 通过菜单「文件 → 导入文本清单」或拖拽 .txt 文件加载
3. 程序解析文本，展示预览表（时间码/操作/标签/状态）
4. 用户确认后点「批量执行」
5. 程序自动 Seek → 截图/截取，进度条显示当前项/总数
6. 完成后生成执行报告（成功/失败/跳过列表）

#### 技术要点

- 解析器：`BatchTextParser` 服务，正则匹配时间码+操作类型
- 执行器：`BatchExecutionService`，复用 `ScreenshotService` + `ClipExtractionService`
- 预览 VM：`BatchPreviewViewModel`，ObservableCollection 展示解析结果
- 进度回调：`onProgress(currentIndex, totalCount, currentItem)`
- 可取消：CancellationToken 贯穿整个批量执行
- 错误恢复：单项失败不中断整批，记录错误继续下一项
- 导出报告：Markdown 格式，含每项时间码/操作/结果/输出路径

#### 测试计划

- `BatchTextParserTests`：各种格式行解析、非法行跳过、边界时间码
- `BatchExecutionServiceTests`：Mock 执行器验证调用顺序、取消传播、错误恢复
- `BatchPreviewViewModelTests`：预览列表绑定、确认/取消交互

### M7 — 数据便携与会话恢复（NO.M，目标 v0.9.0）

用户诉求：自动记录每个素材的拉片数据，再次打开同一视频时自动调取；
全部运行数据集中在同一位置，更换设备后指认数据路径即可直接还原使用状态。

#### 一、数据根便携化

- `config.json` 保留在固定引导位置（`%APPDATA%\Qianlan_App\PianAssistant\config.json`），
  其中新增 `DataRoot` 字段指向真正的数据根；配置必须固定在引导位置，否则无法定位配置
- 数据根下统一存放：`pianassistant.db`、`screenshots\`、`clips\`、`logs\`
- 解析优先级：环境变量 `PIAN_ASSISTANT_DATA_ROOT`（测试隔离用） > `config.DataRoot` > 默认引导目录
- 统一由 `DataRootResolver` 提供，`AppSettingsService` / `ProjectDatabase` / `AppLog` /
  `OutputDirectoryResolver` 一律改为从它取值，不得各自拼路径
- 设置窗新增「数据路径」+「浏览…」（`W2-A-11`）；修改后提示「需重启生效」
- **不自动搬迁旧数据**，仅切换路径并提示（避免误搬大文件）

#### 二、素材会话（内容哈希身份）

- **身份**：内容哈希（SHA-256 流式分块计算），跨设备、改名后仍可识别
- **两级键**（保证打开即用）：先用「路径 + 大小 + 修改时间」快速定位并立即还原；
  随后**后台异步**计算内容哈希作为规范键，算完回写并升级会话记录
- DB 新增 `media_sessions` 表（fingerprint 主键、path、size、mtime、last_position_ms、rate、updated_at）
  及明细（截图清单 / 裁切点 / 入出点 / 笔记），并做 `schema_version` 迁移
- **自动保存**：数据变更后 ~2s 防抖落库；应用关闭与异常退出时兜底 flush
- **自动恢复**：打开视频后静默还原裁切点/入出点/截图清单/笔记/播放位置/倍速，
  并在右下角提示「已恢复上次拉片记录：N 处裁切 / M 张截图 / K 条笔记」
- 设置项：`RestoreSession`（默认开）、`RestorePlaybackPosition`（默认开）
- 与 `.paproj` 分工：自动会话 = 单素材随用随存；`.paproj` = 跨素材 / 跨机打包。两者并存

#### 测试要点

- `DataRootResolver` 优先级；切换数据路径后 DB / 截图 / 日志目录跟随
- 内容哈希：同内容不同路径命中同一会话；哈希在后台线程，不阻塞 UI
- 会话往返：写入 → 重启 → 读取，还原完整（裁切 / 截图 / 笔记 / 入出点 / 位置 / 倍速）
- 防抖落库与异常退出兜底 flush
- 设置关闭时（`RestoreSession=false` / `RestorePlaybackPosition=false`）不恢复对应数据

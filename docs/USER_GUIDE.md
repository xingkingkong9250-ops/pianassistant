# 拉片助手 用户手册（PianAssistant User Guide）

> 适用版本：**v0.9.0**（功能里程碑 M0~M7 已开发完成；正式发布 1.0.0 待用户确认）
> 适用对象：影视编导 / 剪辑师 / 拉片分析人员
> 平台：Windows 10 / 11（x64），本地桌面应用，全程离线可用

---

## 1. 产品简介

拉片助手是一款**本地视频拉片辅助工具**：在回放视频的过程中快速记录时间戳、
截取画面与片段，把"看片"过程中的零散观察沉淀为结构化笔记，最终一键产出可交付的
Markdown 拉片报告。

核心能力：

| 能力 | 说明 |
|---|---|
| 多格式播放 | 基于 LibVLC 引擎，支持 mp4/mkv/avi/mov/flv/wmv/webm/ts/m2ts/mpg 等 |
| 快速截图 | 一键保存当前帧为 PNG/JPG，可按日期/项目自动分目录 |
| 快速截段 | 用 C 键打裁切点，时间轴自动分段，选中段一键导出 |
| 时间轴裁切 | PR 风格红色裁切线 + 顶部三角标记，点击两线之间选中段 |
| 笔记活动流 | 时间戳笔记 + 模板前缀 + 搜索/时间范围筛选 + Markdown/TXT/整理报告导出 |
| 批量文本操作 | 粘贴固定格式的时间码清单，自动批量截图/截段/标记 |
| 截图画廊与标注 | 网格浏览、大图翻页、画笔/箭头/文字/裁剪五工具标注 |
| 片段管理与拼接 | 批量导出队列（进度/取消）、同源片段无损拼接 |

## 2. 安装与首次启动

### 2.1 环境要求

- Windows 10 21H2 及以上 / Windows 11，**64 位（x64）**。
- 应用为自包含（self-contained）发布，运行时已内置 .NET，无需单独安装 .NET SDK。

### 2.2 从发布目录运行（推荐）

构建产物位于：

```
PianAssistant\artifacts\staging\PianAssistant_v0.9.0\
```

双击其中的 **`PianAssistant.exe`** 即可启动。

### 2.3 首次使用必须准备 ffmpeg

截段、批量截图/截段依赖随包携带的 `ffmpeg.exe` / `ffprobe.exe`。**首次从源码克隆运行前**，
请在仓库根目录执行一次：

```powershell
powershell -ExecutionPolicy Bypass -File tools\download-ffmpeg.ps1
```

脚本会从 gyan.dev 下载 ffmpeg essentials 并安装到：

```
src\PianAssistant\Tools\ffmpeg\ffmpeg.exe
src\PianAssistant\Tools\ffmpeg\ffprobe.exe
```

构建时这两个文件会被复制到发布目录的 `tools\ffmpeg\` 下。若缺失该文件，
启动时会弹出提示「缺少必要的依赖文件……请先运行 tools\download-ffmpeg.ps1 下载 ffmpeg」。

### 2.4 数据目录

用户数据统一保存在一个**数据根目录**下，默认位置为：

```
%APPDATA%\Qianlan_App\PianAssistant\
├─ config.json          # 设置（数据路径、输出目录、格式、快捷键、最近文件等）
├─ config.json.backup   # 原子写自动生成的上一份备份
├─ pianassistant.db     # SQLite 数据库（项目/截图/片段/笔记/素材会话）
├─ screenshots\         # 截图默认输出目录
├─ clips\               # 片段默认输出目录
└─ logs\                # 运行日志
```

> 数据根可整体搬迁：在设置窗「数据路径」（W2-A-11）指定任意目录，`pianassistant.db` /
> `screenshots\` / `clips\` / `logs\` 会全部落到该目录下。详见 §2.6。
> 高级：环境变量 `PIAN_ASSISTANT_DATA_ROOT` 可覆盖数据根（便于测试与多副本隔离），
> 优先级高于设置项。

### 2.5 单实例说明

应用是**单实例**的：若已有一个实例在运行，再次双击 exe 不会打开新窗口，而是静默退出。
需要强制重启时，可先结束已有进程（或在开发场景使用仓库自带 `run.bat`，它会自动关闭旧实例后重启）。

### 2.6 数据便携与自动恢复

**数据便携（换设备 / 换路径后还原使用状态）**

所有运行数据集中在**一个数据根目录**（默认 `%APPDATA%\Qianlan_App\PianAssistant\`）。
只需在设置窗「输出设置」页把「数据路径」（W2-A-11）指向你希望的位置（如移动硬盘、云同步盘），
数据库、截图、片段、日志即会统一落到该目录。

- **更换设备 / 重装系统**：把整个数据根目录拷贝到新机器，然后在设置中把「数据路径」指向它，
  重启应用后即可**恢复之前的全部使用状态**（项目、截图、片段、笔记、素材会话记录）。
- 修改数据路径后，提示「需重启生效」；应用**不会自动搬迁**旧数据——请自行拷贝后再切换。
  `config.json` 本身始终留在固定的引导目录（`%APPDATA%\Qianlan_App\PianAssistant\`），
  以便应用能定位到你的数据路径设置。

**素材会话自动保存与恢复（M7 核心）**

打开某个视频时，应用会自动记录该素材上的**裁切点、入/出点、截图清单、笔记、播放位置与倍速**
（「素材会话」），全部保存在数据库中。之后再次打开**同一素材**时会自动还原：

- 身份识别采用**内容哈希（SHA-256）**：即使文件被**改名或换了路径/设备**，只要内容一致，
  仍能识别为同一素材并还原记录（打开瞬间先按「路径+大小+修改时间」快速定位，
  后台再异步计算内容哈希做跨机校正，二者兼顾速度与准确）。
- 之后打开该素材，会看到右下角提示条「已恢复上次拉片记录：N 处裁切 / M 张截图 / K 条笔记」。
- 设置项「**恢复上次拉片记录**」（W2-A-13）与「**恢复播放位置与倍速**」（W2-A-14）默认开启，
  可按需关闭；关闭「恢复上次拉片记录」后不再自动还原任何数据。
- 会话数据与应用自动保存（约 2 秒防抖落库），退出、切换素材或异常退出时都会兜底保存。

> 说明：素材会话（单素材随用随存）与 `.paproj` 手动项目（跨素材打包）**分工并存**：
> 日常拉片用自动会话即可；需要交付/归档多个素材时用「💾 保存 / 📦 打包」。

### 3.1 四大区域

- **顶部导航栏 W1-R1**：Logo+标题，「�」展开/收起左侧播放列表（W1-R1-23）；

### 4.8 长按连续与步长说明

- **方向键左右**：单步移动"方向键帧步长"（默认 **5 帧**，可在设置中配置，范围 **1~600 帧**）。
  - **长按连续**：按下后 300ms 触发首次操作，随后每 **50ms** 重复一次，松键即停止。
  - **倍率乘算**：当播放倍速 ≥ 1.0× 时，单步帧数 = 帧步长 × 倍速。例如步长 5 帧、倍速 2×，
    按一次 →/← 实际移动 **10 帧**（倍速 < 1.0× 时不乘算，仍按 1.0× 计）。
- **方向键上下**：每次按"倍速步长"调整倍速（默认 **0.25×**，可在设置中配置，范围 **0.05~1.0**），
  同样 300ms 后进入 50ms 连续重复；倍速被夹紧在 `0.25× ~ 最高倍率` 之间。
- **高速档自动静音**：倍速超过 **4×** 时会自动禁用音轨（无声）——音频时钟无法支持
  超高速播放，禁用后高倍速才能真实生效；回落到 4× 及以下时自动恢复声音。
- **视觉反馈**：每次方向键操作，视频中央会叠加一个图标 + 文字面板（如 "◀ 5 帧"、"▲ 2.00×"），
  600ms 后淡出。

> **说明（与设置窗略有差异）**：设置窗的「快捷键」页列出了达芬奇风格的动作表（含
> `Shift+←/→`、`Ctrl+←/→`、数字键跳转百分比等预设）。这些条目中，左右方向键的
> "单步/长按"行为由主窗口的方向键处理逻辑统一接管；部分预设（如数字键百分比跳转）
> 在当前窗口层未绑定，暂不生效。以本章上表为准。

## 5. 核心工作流示例

### 5.1 打开视频 → 播放/暂停 → 逐帧定位 → 截图

1. 点击顶部「📂 打开视频」（W1-R1-16），弹出系统文件对话框；支持 `Ctrl`/`Shift` 多选批量加入播放列表（Windows 原生选择逻辑），打开后自动播放第一个并加入播放列表（左侧常驻面板）。也可直接把多个视频文件拖入视频画面。
2. 按 `Space` 暂停。用 `←` / `→` 逐帧定位（可长按连续微调）；倍速较高时单步跨度会更大。
3. 找到目标画面后按 `S` 截图。
4. 截图自动出现在侧边栏「笔记 → 📷 截图」子标签（W1-C2-A）与截图画廊（🖼）中。
5. 需要缩放时间轴精确定位时，在时间轴（W1-R3）上滚动鼠标滚轮放大到合适倍数。

### 5.2 用 C 键打多个裁切点 → 自动分段 → 选中段 → 导出片段

1. 打开视频并定位到一段的**起点**，按 `C` 添加第一个裁切点（工具栏「🔴 裁切」等效）。
2. 定位到该段**终点**，再按 `C` 添加第二个裁切点。时间轴出现红色竖线 + 顶部三角。
3. 侧边栏「笔记 → ✂ 片段」（W1-C2-B）自动按裁切点分段，显示编号、起止时间与时长。
4. 在时间轴上点击**两个裁切点之间**的区域选中该段（半透明红色高亮）。
5. 按 `Ctrl+E` 或点工具栏「📤 导出」导出该段；文件写入数据目录下的 `clips\` 子文件夹（可在 W2 设置「数据目录」）。
6. 打错了可用 `Backspace` 撤销最后一个裁切点，或 `Ctrl+Shift+C` 清空。

> 提示：也可以不打裁切点，直接用 `I`/`O` 标记入/出点，点工具栏 ✂ 截取该入出点片段。

### 5.3 拉片笔记：记录 → 查看活动流 → 搜索/筛选 → 导出报告

1. 打开「笔记」面板，切到「📝 活动」子标签（W1-C2-T3）。
2. 在底部模板下拉框（W1-C2-C-07）选择模板（如"构图"），输入观察内容，按 `Enter` 或点「添加」。
   笔记会自动带上模板前缀（如 `[构图] `），并记录当前播放位置。
3. 需要再次定位时，按 `[` / `]` 在活动条目之间前后跳转；或直接点击活动条目。
4. 用顶部搜索框（W1-C2-C-01）按关键词过滤；用「范围」起/止输入框（mm:ss 或 hh:mm:ss）按时间筛选。
5. 右键活动条目可「✏ 编辑」（内联输入，Enter 提交 / Esc 取消）或「🗑 删除」。
6. 导出：
   - 点「📄 整理导出」→ 生成结构化 Markdown 报告（含统计、按位置排序的时间线活动、分段汇总）。
   - 点「📤 导出」→ 保存为 `.md`（Markdown）或 `.txt`（纯文本），均含时间码。

**模板清单**（含"无模板"共 7 项）：无模板 / 构图 / 灯光 / 节奏 / 转场 / 表演 / 剪辑。

## 6. 批量文本操作

入口：顶部工具栏「📋」（W1-R1-07）打开「批量操作」窗口（**W4**）。

### 6.1 指令文本格式

每行一条指令；空行忽略；以 `#` 或 `//` 开头的行视为注释。

| 格式 | 含义 |
|---|---|
| `HH:MM:SS 截图 标签` | 在该时刻截图（标签可省略） |
| `HH:MM:SS-HH:MM:SS 片段 标签` | 截取起止时间段为片段（标签可省略） |
| `HH:MM:SS 标记 标签` | 在该时刻添加一条笔记（**标签必填**） |
| `HH:MM:SS` | 仅添加一个裁切点（不导出） |

**容错规则：**

- 时间：`HH:MM:SS`、`HH:MM:SS.mmm`（毫秒可选）、`MM:SS`、`MM:SS.mmm`，也接受纯秒数；允许乱序。
- 中英别名（英文不区分大小写）：
  - 截图 = `screenshot`
  - 片段 = `clip`
  - 标记 = `笔记` = `note`
  - 裁切点 = `裁切` = `cutpoint` = `cut`
- 全角冒号 `：`、全角空格、em/en 破折号（`—`/`–`）均会自动转换为半角。
- 时间段后的关键字可省略；若填写则只允许 `片段` / `clip`。
- 解析失败的行**不会中断**整批，会在预览中标记错误并说明原因（行号 + 原因）。

### 6.2 可直接复制的示例清单

```
# 拉片清单示例 — 以 # 开头的行为注释
# 单点截图
00:01:23            截图 构图-三分法
00:00:42.500        截图 光影-逆光
# 片段截取（入点-出点）
00:01:30-00:02:15   片段 转场-叠化
00:03:00-00:03:10   片段 节奏-快切
# 仅标记（不导出）
00:05:00            标记 镜头-全景
00:05:30            标记 镜头-特写
# 裸时间 = 裁切点
00:04:20
# 英文别名与 MM:SS 写法同样可用
01:20 screenshot lighting
01:00-02:30 clip transition
```

### 6.3 操作步骤

1. 打开「批量操作」窗口（W4）。左侧是「指令文本」编辑区（W4-B-01）。
2. 点击「📂 载入文件」（W4-T-01）从 `.txt` 载入，或直接把清单**粘贴**到左侧文本框。
3. 点击「🔍 解析预览」（W4-T-02）。右侧「解析预览」表格（W4-B-03）逐行显示
   **行号 / 类型 / 时间 / 标签 / 状态 / 错误**；顶部统计（W4-T-03）显示「共 N 条 · 有效 M · 错误 K」。
4. 确认无误后点「▶ 执行」（W4-F-03）：
   - **标记 / 裁切点**：立即写入笔记活动流与时间轴（无需视频）。
   - **截图 / 片段**：需要先在主窗口打开视频；程序自动 Seek 到各时间点执行，
     底部进度条（W4-F-01）显示进度，右侧切换为「执行结果」（W4-B-04：状态 / 输出 / 耗时 / 错误）。
5. 执行过程中可点「✕ 取消」（W4-F-04）中止；已完成项保留。

### 6.4 常见错误提示含义

| 预览中的错误 | 含义与处理 |
|---|---|
| `无法识别的时间「xxx」` | 行首时间码格式不对，检查是否写成 `HH:MM:SS` |
| `标记指令需要标签文本` | `标记`/`笔记` 行未写标签 |
| `片段指令需要时间段（HH:MM:SS-HH:MM:SS）` | 只写了单个时间却用 `片段` 关键字，应改为起-止时间段 |
| `结束时间必须晚于起始时间` | 片段行的出点 ≤ 入点 |
| `时间段后仅支持「片段/clip」指令` | 时间段后写了其它关键字 |
| `无法识别的指令关键词「xxx」` | 关键字拼错/别名不在支持列表中 |

> 执行时若未打开视频而清单含截图/片段指令，窗口会提示「请先在主窗口打开视频文件」。

## 7. 裁切数据导入 / 导出

入口：侧边栏「笔记 → ✂ 片段」顶部（W1-C2-B-02 / W1-C2-B-03）。

**导出（⬇ 导出裁切）** 生成文本清单（UTF-8 无 BOM），格式与批量清单兼容：

```
# PianAssistant 裁切点导出 v1
# 每行一个裁切点：HH:MM:SS；片段段：HH:MM:SS-HH:MM:SS 片段 标签
00:00:00-00:00:30 片段 #1
00:00:30
00:00:30-00:01:10 片段 #2
00:01:10
00:01:10-00:02:00 片段 #3
```

- 每个裁切点单独一行（`HH:MM:SS`，毫秒非零时带 `.mmm`）。
- 相邻裁切点之间（含起点 `00:00:00` 与视频结尾）会自动生成 `起-止 片段 #N` 行。

**导入（⬆ 导入裁切）** 读取上面的文本文件：

- 裁切点行用于**整体替换**当前时间轴上的裁切点（去重、升序）。
- 片段行（`起-止 片段 …`）会加入「📦 片段」批量导出队列（需要源视频才能构造范围）。
- 注释行与解析失败的行自动忽略。

**往返场景**：在一台机器上拉完片导出裁切清单 → 拷到另一台机器（或另一个副本）打开同一视频 →
「⬆ 导入裁切」即可复用全部切点与分段，无需重新逐段标记。

## 9. 片段管理与拼接

入口：导航标签「📦 片段」（W1-R1-04）切换到「片段批量导出」面板（**W1-C3**）。

- **队列（W1-C3-03）**：列出每个片段的入点→出点、时长、标签、状态、单项进度。
- **搜索（W1-C3-01）**：按标签筛选，支持 `#标签`。
- **全部导出（W1-C3-04）**：把队列中全部完整片段批量导出（流复制，快速无损）；

  先流复制导出各临时段，再用 ffmpeg concat 合并）。跨源（不同视频文件）或含不完整片段时会报错。

单条片段导出也可在「笔记 → ✂ 片段」列表中点该段的「📤」。

## 11. 常见问题（FAQ）

**Q1. 双击 exe 没有任何反应？**
应用是单实例。若已有一个实例在运行，新进程会静默退出（不弹窗、不新开窗口）。
请检查任务管理器中是否已有 `PianAssistant.exe`，结束旧进程后重试；或使用 `run.bat`（会自动关闭旧实例再启动）。

**Q2. 视频打不开 / 画面黑屏？**
- 确认文件格式在支持列表内（mp4/mkv/avi/mov/flv/wmv/webm/ts/m2ts/mpg 等）。
- 确认文件未被其它程序独占、路径中无异常字符。
- 首次请确认已运行 `tools\download-ffmpeg.ps1`；LibVLC 解码库随发布包自带。

**Q3. 截图或片段导出失败？**
最常见原因是 `ffmpeg.exe` 缺失：请确认发布目录下存在 `tools\ffmpeg\ffmpeg.exe`，
如缺失请运行 `tools\download-ffmpeg.ps1` 后重新构建/拷贝。

**Q4. 字幕怎么加载？**
将 `.srt/.ass/.ssa/.vtt/.sub` 字幕文件**拖拽到视频画面区**（W1-R2-01）即可加载外挂字幕。
（拖入非字幕文件不会生效。）

**Q5. 倍速超过 4× 后没有声音？**
正常现象。LibVLC 在高倍速播放（约超过 4×）时会静音音频，仅快速播放画面。
倍速上限可在设置中调整（2×~32×，默认 8×）。

**Q6. 数据保存在哪里？如何备份笔记？**
都在 `%APPDATA%\Qianlan_App\PianAssistant\`：
- 设置与最近文件：`config.json`（另有 `config.json.backup`）。
- 数据库：`pianassistant.db`。
- 导出的截图/片段：`screenshots\` / `clips\`（或你在设置中指定的目录）。

备份建议：直接复制整个 `PianAssistant` 数据目录；笔记的长期留存请在「📝 活动」面板
用「📄 整理导出 / 📤 导出」导出为 Markdown/TXT 文件另行保存。

**Q7. 时间轴太挤 / 看不清裁切点？**
在时间轴区域滚动鼠标滚轮放大（0.5×~50×），右上角显示当前缩放倍数；放大后可用横向滚动条移动。

**Q8. 换电脑后怎么恢复之前的状态？**
把原机器的整个**数据根目录**（默认 `%APPDATA%\Qianlan_App\PianAssistant\`）整体拷贝到新机器
（或移动硬盘 / 云同步盘），在新机器上打开设置 → 「数据路径」（W2-A-11）指向该目录，重启应用即可。
数据库、截图、片段、笔记与素材会话记录都会一并恢复。
另外，即使素材文件的路径变了或改了名，只要**内容一致**，再次打开时仍会自动还原其拉片记录
（素材身份用内容哈希识别）。详见 §2.6。

**Q9. 为什么输入法总被切回英文？**
应用启动时会把输入法**强制切换为英文模式**，避免中文输入法吞掉 `S`/`C`/`F` 等单键快捷键；
从其它窗口切回主窗口时也会自动强制一次。需要输入中文笔记时，**点进文本框后再按 `Shift`**
切换中文即可；离开文本框后会自动恢复英文模式。关闭应用时会还原你启动前的输入法状态。

## 12. 文件与目录结构

### 12.1 应用运行目录（发布包）

```
PianAssistant_v0.9.0\
├─ PianAssistant.exe           # 主程序
├─ libvlc / LibVLCSharp 相关 DLL # 播放引擎
├─ tools\ffmpeg\
│  ├─ ffmpeg.exe
│  └─ ffprobe.exe
└─ ...（其余 .NET 运行时文件）
```

### 12.2 用户数据目录

见 §2.4。`.paproj` 项目文件为 JSON 格式（项目定义），数据库为 `pianassistant.db`（SQLite）；
素材会话（自动保存的裁切/截图/笔记/位置）也存放在该数据库中。

> 说明：项目与最近文件的交互入口已提供——顶部工具栏 `💾` 保存项目（W1-R1-18）、`📁` 打开项目
> （W1-R1-19）、`📦` 打包导出 zip（W1-R1-20）、`📥` 导入 zip（W1-R1-21）；
> "📂 打开文件"右键列出最近文件（W1-R1-22）。

### 12.3 导出产物命名规则

- **截图**：`源文件名_时间码_日期时间.扩展名`，例如
  `Demo_00-01-23-500_20261014153000.png`
  （时间码为文件名安全写法；重名时自动追加 `_2`、`_3`…）。
- **片段**：`源文件名_入点时间码-出点时间码.mp4`，例如
  `Demo_00-01-30-000-00-02-15-000.mp4`（重编码模式追加 `_rec`）。
- **标注副本**：`原截图名_annotated.png`。
- **裁切清单**：`.txt`（UTF-8 无 BOM，首行版本头 `# PianAssistant 裁切点导出 v1`）。
- **笔记/报告导出**：`.md`（Markdown）或 `.txt`。

### 12.4 日志

- 运行日志：开发场景由 `run.ps1` 写入 `%TEMP%\PianAssistant.run.log`。
- 调试信息：应用内部异常通过 `Debug.WriteLine` 输出（需调试器查看）。
